The existing installation at `C:\Flutter\flutter` was upgraded with normal
`flutter upgrade`, without `--force`. It initially refused because of untracked
Gradle build output in the SDK. Those files were preserved intact under the
ignored `build/sdk-upgrade-backup/flutter-gradle-bin-3.32.2/` directory before
retrying. No tracked SDK edits were discarded. The tool regenerated SDK caches
and workspace lockfiles as part of its normal upgrade.

The app declares Dart `^3.13.0` and Flutter `>=3.50.0`; CI should pin the exact tested
Flutter version rather than relying on these broad compatible ranges. The SDK's
`flutter_localizations` now requires `intl ^0.20.3`, so the previous exact 0.20.2
constraint could not resolve on the new SDK. The new exact app pin is 0.20.3.

`pubspec.lock` records the complete reproducible package set. Its native path-provider
updates introduce JNI/native-asset dependencies; generated Windows FFI registration
and macOS plugin registration were regenerated by Flutter, not hand-edited.
Other notable transitive versions: path_provider 2.1.6, path_provider_android 2.3.1,
path_provider_foundation 2.6.0, jni 1.1.2, objective_c 9.6.4,
material_color_utilities 0.13.0, vector_math 2.4.4, test_api 0.7.14.
Secure-storage and lint package majors were deliberately retained.

## Compatibility changes

- Migrated application and test Material imports and localization delegates to
  the official standalone package. Flutter 3.50 deprecates the old bundled library.
  This is an API migration, not a new design or navigation system.
- Replaced deprecated dropdown `value` initialization with `initialValue`.
  Existing selection/mapping/property tests still exercise the behavior.
- Added transparent Material surfaces inside decorated cards, the Reception list
  and the older workspace sidebar. The new toolkit diagnosed invisible ListTile
  ink/background layers. Callbacks, styles, records and permissions remain intact.
- Fixed a pre-existing `dart:ui` alias collision with the `ui()` translation
  function. Removed redundant imports; excluded ignored `build/**` scratch files
  from application analysis instead of adding development-script packages to the app.
- Production Hungarian default, English availability, catalogs and preference
  persistence are preserved. Existing English-copy workflow tests now select an
  explicit English test locale. Two new tests cover Hungarian default and language
  persistence; no behavioral assertions were deleted. Two close-button tests now
  use the existing semantic tooltip instead of the old text glyph.
- Screenshot tests can read installed macOS fonts as well as Windows fonts, to
  prepare the host tests for Codemagic. No OS fonts were bundled or redistributed.
  Actual macOS test execution remains unverified.
- Android uses the new compilerOptions DSL. Flutter's migrator added legacy Kotlin
  and DSL compatibility flags for the existing plugins. A non-fatal warning remains
  that the app should eventually migrate to built-in Kotlin; it does not block this
  pinned SDK build. No validation checks were bypassed with build-skip flags.

and no Android/Windows scaffold was replaced. The bundle identifier remains
`com.delvane.delvaneBusiness`.

- Added the Flutter SDK's CocoaPods Podfile with iOS 15 and RunnerTests inheritance.

  is left to the macOS Flutter build; Pods, credentials and signing files are not added.

- Plist syntax, SceneDelegate project references and deployment-target consistency
  were checked locally. This is **not** an Xcode compilation or CocoaPods validation.

## Codemagic recommendation

Select **Flutter 3.50.0**, **Xcode 27.2**, **CocoaPods 1.17.0** and a macOS Apple
silicon builder. Select `apps/delvane_business` as the Flutter project directory.
Pin the Flutter version in the workflow editor or YAML; do not use the moving
`stable`/`latest` aliases for the regression baseline. Codemagic documents Xcode
27.2 and CocoaPods 1.17.0 on that image; this combination is a recommendation for
the first macOS validation run, not a claim it has already passed remotely.

Suggested **unsigned, non-publishing** workflow (provided for review; not installed
as an active root CI configuration):

```yaml
workflows:
  delvane-ios-validation:
    name: Delvane iOS validation
    instance_type: mac_mini_m2
    environment:
      flutter: 3.50.0
      xcode: 27.2
      cocoapods: 1.17.0
    scripts:
      - name: Verify toolchain
        script: |
          cd "$CM_BUILD_DIR/apps/delvane_business"
          flutter --version
          flutter doctor -v
          xcodebuild -version
      - name: Resolve locked dependencies
        script: |
          cd "$CM_BUILD_DIR/apps/delvane_business"
          flutter pub get --enforce-lockfile
      - name: Analyze and test
        script: |
          cd "$CM_BUILD_DIR/apps/delvane_business"
          flutter analyze
          flutter test
      - name: Build unsigned iOS application
        script: |
          cd "$CM_BUILD_DIR/apps/delvane_business"
          flutter build ios --release --no-codesign
    artifacts:
      - apps/delvane_business/build/ios/iphoneos/*.app
```

The unsigned build validates compilation; it does not produce an installable,
signed physical-iPhone release. For simulator QA, use `flutter build ios --simulator
--debug` on macOS. Provisioning, Apple team selection, signing, Keychain/device tests
and any approved TestFlight workflow remain separate. No production secrets are
needed for this validation recipe. The backend remains the guarded disposable
workspace; iPhone connectivity needs a separate safe development connection rather
than Android's `adb reverse`.

Sources: [Flutter stable archive](https://docs.flutter.dev/install/archive),
[official Material migration](https://docs.flutter.dev/release/breaking-changes/material-ui-and-cupertino-ui),
[Codemagic Xcode 27.2 image](https://docs.codemagic.io/specs-macos/xcode-27-2/).
