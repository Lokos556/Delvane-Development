## Implementation findings and this assignment

- Existing `government_security.py` correctly confines credential references, checks RSA/key match/validity, uses the3-day margin in status/TLS and constructs verified TLS. It does not establish property/software binding, current issuer-chain/revocation authorization or a WS-Security profile. These limitations remain explicit; shared behavior was not weakened.
- Existing `ntak_contracts.py` safely validates XML/business XSDs, forbids DTD/entities/external schema imports and supplies SOAP framing. Body validation is not signature verification. `ntak_transport.UnresolvedOfficialTransport` remains the production/default boundary and still raises `signature_profile_unresolved`.
- New **`ntak_security.py`** provides explicit exclusive-C14N, deterministic RSA SignatureValue generation/checking for the three documented signature algorithms, Base64 DER encoding, literal CN/tax checks,3-day certificate validity,300-second Created-age validation and a metadata/property/environment-bound verified TLS context requiring an explicitly approved endpoint and CA file. It reuses `government_security.credentials`; no second credential store is introduced.
- `Binding`/`binding.json` are **local operator policy**, not an official NTAK certificate or wire format. Metadata includes system=NTAK, organization_id, property_id, environment, registration_id, provider_vat, software_id, endpoint, credential_reference and certificate_sha256. Scope and endpoint approval are checked before key loading. Local minimumTLS1.2, default port443, fingerprint pinning and exact attribute comparisons are explicitly local fail-closed decisions. No supplied key is assumed authorized merely because these checks pass.
- `ntak_diagnostics.py` distinguishes local security-preflight codes from the official catalog and recognizes the two documented error-key spellings. `ntak_reporting.py` preserves fixed local failure codes and records redacted GLOBAL/connection guidance in Task15 diagnostics. `ntak_evidence.py` retains those safe codes in Task17 exports. No diagnostic prose or credential material is exposed.
- New `tests/test_ntak_security.py` uses only generated synthetic certificates/keys inside guarded tests, independent public-key verification and in-memory TLS. SignatureValue verification checks **only SignedInfo's cryptographic value**, not Reference resolution, digest coverage, duplicate-ID/wrapping safety or NTAK response trust. It cannot turn an envelope into a trusted response. No concrete SignatureProfile, reference resolver, complete signer, HTTP connector, certificate downloader or enablement flag was added.
- VIZA reuse is limited to design/test primitives: existing credential loader, cryptography, verified SSL and MemoryBIO tests. Its `reportingID|arrivalUUIDs|timestamp` RSA-SHA256 string, certificate CN/reporting-ID mapping, zero-day expiry margin, THF trust roles, outer-security assumptions and retry semantics are **not transferred to NTAK**. VIZA source files remain unchanged.
