Classification scope: **Fully implemented** means the stated existing foundation is present, not official VIZA acceptance. **Partially implemented** means usable code exists but does not yet satisfy the complete VIZA requirement. **Missing** means the required VIZA behavior was not found. **Blocked** means external information/access/device verification is needed. A missing implementation is not reclassified as externally blocked merely because test credentials have not arrived.

## Priority findings from actual code

1. **Wrong trigger if legacy outbox were sent as VIZA arrival:** `app.py:verify_guest_identity` queues `guest.registration_verified` only when whole reservation registration becomes complete; `_queue_government_events` also queues reservation changes. V700 requires each real guest arrival/departure. Preserve the existing gate until a reviewed migration/consumer separates legacy preparation records from actual THF jobs.
2. **Original data cannot be reconstructed safely:** browser parse results flatten names/codes; user edits retain a scalar camera scan_method. Ingestion overwrites core fields; scan metadata contains only changed field names. Never reinterpret those old snapshots as trustworthy unchanged scans. Mark legacy provenance explicitly unavailable and request reviewed rescan/manual source as appropriate.
3. **Plaintext PII copies and mutable previews:** `guest_records` stores full_name/DOB/nationality/document type/number; `_queue_government_events` embeds them in plaintext; `_government_payload` reconstructs previews from current live rows; `government_preview` saves the resulting plaintext preview. A new immutable encrypted VIZA capture must not duplicate these paths or log signatures/raw documents/identity values. Existing privacy controls are valuable but incomplete.
4. **Reader normalization is not a wire contract:** `parseNames` produces components but TD parsers return only full_name; nationalityFromMRZ returns human labels; front/back code fills missing birth_name from full_name. Corrected/accented UI text cannot replace the unchanged original group. Preserve separate source values and review transformations, not guessed inverse mapping.
5. **No usable THF visit identity yet:** one actual group action can contain multiple guests; a physical transfer creates another occupancy segment. Arrival UUID must be scoped to the logical guest visit and survive transfers/restarts, not be copied from group events or segment changes. Erroneous-arrival closure is terminal for that UUID.
6. **Network/certification flags are not readiness proofs:** VIZA developer-readiness checks string presence for module_path/registration_id; the worker makes no SOAP call. It does not check live trust/signatures or THF health. Existing certified/submission_enabled UI flags must not imply those checks passed.

These are development findings, not new code changes. Requests, operational databases and real guest records were not inspected.
